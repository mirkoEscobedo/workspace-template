## Product boundary

workspace-template owns Adaptive Delivery methodology, read-only embedded skill access, repository inspection, verification, and sealed thin-state migration. Package managers own dependencies and lockfiles. Hosts and repository owners own model, agent, permission, skill, and capability availability.

The canonical product assets are `assets/schemas` and the 13 roots declared by `assets/skills/inventory.json`. Frontier orchestration skills, ticket repair/implementation/review skills, retrofit writers, `write-skill`, presets, generated host configuration, project-agent templates, tooling packs, copied projections/baselines, JavaScript production code, and JavaScript smoke harnesses are deleted from active context.

Required for the first public alpha: read-only skill access, native help/strict arguments/stable exits, update status, package-manager-independent upgrades, project schema v2, platform artifact identity, explicit platform rejection, and Windows cancellation/descendant qualification.

Deferred until demonstrated demand: rich workspace inspection, dependency-aware affected verification, `create`, Dart/Flutter and Node Inspector adapters, and non-Windows binaries. Permanently rejected: projections and copied-skill merges, presets, dependency/tooling execution, generated methodology trees, alignment/restructuring executors, universal script wrappers, and Frontier orchestration.

Authenticode signing with RFC 3161 timestamping is mandatory. Package namespace/ownership, access, maintainers, recovery owners, and signing custodian are human decisions.
