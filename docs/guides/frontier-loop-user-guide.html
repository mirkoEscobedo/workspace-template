Local-file agentic development

Plan clearly. Mutate narrowly. Verify independently.

Frontier Loop lets one continuous coordinator session create or retrofit a repository, resolve the route with Wayfinder, compile vertical ticket contracts, delegate bounded roles, keep one writer by default, and land accepted work serially—without requiring GitHub Issues, webhooks, or a fleet of chats watching the repository.

GPT-5.6 Sol high — coordination/planning GPT-5.3-Codex high — engineering roles Immutable plans Project-owned skills One writer by default Serial authority

1. The mental model

Wayfinder → Compile Master Plan → compute the local ready frontier → parallel read-only preflight → one write-capable implementer by default → independent review lenses → targeted repair → neutral serial integration → recompute the frontier and continue
Operating rule: parallelize discovery and evidence; serialize overlapping mutations and authority transitions.

The current chat or harness session remains the coordinator. It reads durable repository files, delegates fresh bounded roles when available, and continues through ordinary tickets. It stops for completion, a real human authority gate, a material contradiction, unsafe scope expansion, or unrecoverable verification—not merely because one subtask ended.

Wayfinder

Resolves destination, facts, decisions, authority gates, research/prototypes, and remaining fog. It does not freeze detailed tickets while route-changing questions remain open.

Compiled contracts

Freeze ticket-specific behavior, dependencies, conflict keys, read/write sets, risk, budgets, review axes, verification, evidence, and stop conditions.

Frontier scheduler

Selects only unblocked, conflict-free work. Read-only work can overlap. One writer is the default; a second requires proven disjoint scope.

Independent evidence

Specification/authority, code/test, and operations/security reviews are separate lenses. Repairs invalidate only affected evidence.

2. Install and run

Node.js 24 or newer is required. The CLI has no third-party runtime dependency.

# Run from a published package or local tarball
npx workspace-template --help

# After installing locally
workspace-template --version

Git is recommended for clean-root checks, HEAD fingerprints, affected-module detection, and worktree checkpoints. Non-Git directories remain usable with documented limitations.

3. Create a new agentic project

npx workspace-template create inventory-api \
  --project typescript \
  --style functional-core \
  --tdd pragmatic \
  --agents codex,opencode

Available starters are TypeScript, JavaScript, React with TypeScript, Rust, and Flutter/Dart. Styles are simple, functional-core, and clean. Selecting a style chooses a direction; it does not require empty layers or one interface per concrete type.

# Offline/review-only generation
npx workspace-template create inventory-api \
  --project typescript \
  --no-install --no-git --yes
Existing repository? Use adopt or retrofit. Do not use create --force as the normal retrofit path.

4. Retrofit an existing repository safely

Inspect first

npx workspace-template inspect . --workspace all --json

Inspection is read-only. It records Git state, stack evidence, package-manager and lockfile ownership, real commands, instructions/skills, ticket tracks, workspace modules, and conflicts.

Persist the exact adoption plan

npx workspace-template adopt . \
  --dry-run --json \
  --plan-out ../my-repository-adoption.json

Apply only that reviewed plan

npx workspace-template adopt . \
  --apply-plan ../my-repository-adoption.json

Apply verifies the plan’s integrity and repository/file/Git fingerprints. It does not replan. A materially changed repository requires a new plan.

Adoption may add or manageAdoption preserves
.agentic/**, docs/agent/**, canonical skills and baselinesapplication source and tests
approved full instructions, managed blocks, or proposalsmanifests, lockfiles and dependencies
conflict-free harness projections and role configurationREADME.md, CI and deployment files
ticket contracts/frontier/evidence metadataunmanaged custom skills/instructions unless explicitly integrated

Default conflict policy is propose. Use managed-block to update one delimited block or fail to require manual integration. Broken/duplicate markers always block.

5. Capture planning with Wayfinder

Use the repository Wayfinder when the work should become durable repository state:

Use the repository Wayfinder skill for this goal.
Write the map under docs/agent/wayfinding/<effort>/.
Keep source-backed facts, my decisions, your inferences, open decisions,
authority gates, evidence, and fog distinct. Do not compile tickets while
an unresolved decision can materially change the route.

When stable:

Use Compile Master Plan on the approved Wayfinder map. Produce vertical local
tickets with dependency edges, conflict keys, expected write sets, risk lanes,
verification levels, independent review axes, architecture/process budgets,
and stop/split conditions.

The durable output normally includes:

docs/tickets/<track>/
  master-plan.md

    ticket.md

6. Execute the local frontier

Use Execute Frontier. Continue from local repository files in this coordinator
session. Parallelize read-only investigation and independent review, keep one
writer by default, land accepted changes serially, and continue until the goal
is complete or a real human/contradiction/safety gate is reached.

Ticket-level correctness remains strict:

  1. Implement one frozen contract through vertical public-interface TDD.
  2. Collect fresh verification at the required levels.
  3. Run independent review axes without relying on the implementer’s narrative.
  4. Repair only failed findings within the same scope.
  5. Re-review invalidated axes.
  6. Integrate only after all required gates pass.
Risk laneDefault treatment
0 — mechanicalcontroller or one worker, targeted automation/combined review
1 — local behaviorone writer, code/test review, L0–L2 verification
2 — cross-moduleone writer initially, spec plus code/test review, integration wave
3 — authority-criticalexactly one writer, authority + code/test + ops/security, broad landing gate and human approval where required

8. Codex setup

Generated projects receive .codex/config.toml, role definitions under .codex/agents/, and process guards through hooks.

model = "gpt-5.6-sol"
model_reasoning_effort = "high"

[agents]
enabled = true
max_concurrent_threads_per_session = 3
default_subagent_model = "gpt-5.3-codex"
default_subagent_reasoning_effort = "high"

[features]
hooks = true

Planner/scout/reviewer role files use read-only sandboxes. Implementer, repairer, and integrator use workspace-write sandboxes. Start with one writer and no more than two read-only children. Stop/SubagentStop hooks reject completion while owned process leases remain open.

9. OpenCode setup

opencode.json and .opencode/prompts/frontier-loop/ define the equivalent role split, models, prompts, step limits, and tool permissions. The orchestrator can call approved roles. Read-only roles cannot edit. Write workers cannot recursively create a new writer tree.

OpenCode discovers projected Agent Skills under .opencode/skills/ and the shared .agents/skills/ path. Replace model IDs only when your configured provider exposes different identifiers.

10. Install the ChatGPT Wayfinder skill

The ChatGPT edition is deliberately a single self-contained file:

chatgpt-skills/wayfinder-planner/SKILL.md
  1. Create or keep a folder named wayfinder-planner.
  2. Place the supplied SKILL.md inside it.
  3. In ChatGPT, open Skills, select +, then Upload from your computer.
  4. Upload the folder/ZIP prepared by the release or the skill file in the structure accepted by the UI.

Use it to capture planning in the conversation first:

Use Wayfinder Planner for this effort. Maintain the visible planning ledger,
distinguish source-backed facts, my decisions, and your inferences, and keep
route-changing questions open as fog. When stable, compile the master plan and
produce the local execution handoff.
Do not install the repository edition in its place. The repository Wayfinder expects companion skills and durable local paths; the ChatGPT edition includes the compiler/templates inline.

11. Monorepos and verification

# Inspect all detected modules
workspace-template inspect . --workspace all --json

# Verify every module dependency-first
workspace-template verify . --scope all --concurrency 3

# Verify changed owners plus dependents
workspace-template verify . \
  --scope affected --affected-from origin/main --concurrency 3

# Verify selected modules
workspace-template verify . \
  --scope module --module web --module core

Discovery supports recognized npm-family workspaces, Cargo workspaces/path dependencies, Flutter/Dart package layouts, and polyglot roots. Unknown members remain visible as opaque nodes. Overlapping roots, cycles, duplicate IDs, case collisions, or ambiguous lock ownership block rather than guess.

12. Explicit tooling and dependency transactions

# Plan only
workspace-template tooling plan . \
  --module web --pack quality \
  --plan-out .agentic/plans/web-quality.json

# Apply exactly that plan
workspace-template tooling install . \
  --apply-plan .agentic/plans/web-quality.json \
  --allow-network --lifecycle-scripts deny

Supported adapters are npm, pnpm, Yarn, Bun, Cargo, and Flutter/Dart. Plans store executable, argv, cwd, expected paths, network/lifecycle requirements, dependency kind, structured config/script integration, verification, and rollback limits.

Authority is explicit: registry/network access, runtime dependencies, and lifecycle scripts need dedicated flags. Native package managers own lockfiles. Unexpected paths fail and trigger bounded restoration.

13. Upgrade project-owned skills

workspace-template skills update . --check

workspace-template skills update . \
  --skill tdd --skill execute-frontier \
  --plan-out .agentic/plans/skills.json

workspace-template skills update . \
  --apply-plan .agentic/plans/skills.json

The updater compares baseline, local, and incoming trees. Clean non-overlapping edits merge. Real overlap, local-edited deletion, executable/binary divergence, or broader tools/permissions block until explicitly resolved. Default selected-set apply is atomic; --partial is an explicit alternative plan.

14. Move source without changing behavior

workspace-template restructure plan . \
  --module web \
  --move 'src/old/policy.ts=>src/domain/policy.ts' \
  --checkpoint worktree \
  --plan-out .agentic/plans/move-policy.json

workspace-template restructure apply . \
  --apply-plan .agentic/plans/move-policy.json

This command owns file moves and the static references/config fields required by those moves. It does not own business behavior, new dependencies, ports, services, repositories, transaction changes, or cross-package ownership.

The scanners are conservative, location-aware subsets—not full compiler frontends. Computed imports, generated code, macros, custom loaders, ambiguous aliases, or unsupported relationships become blockers/manual work.

15. Align one architecture slice

workspace-template align plan . \
  --module orders \
  --use-case src/orders/process-order.ts \
  --style functional-core \
  --characterization required \
  --max-files 8 --max-diff-lines 400 \
  --plan-out .agentic/plans/process-order.json

Manual mode

workspace-template align execute . \
  --apply-plan .agentic/plans/process-order.json \
  --executor manual

# Complete only the emitted task and structured result, then:
workspace-template align resume . \
  --apply-plan .agentic/plans/process-order.json

Configured command wrapper

workspace-template align execute . \
  --apply-plan .agentic/plans/process-order.json \
  --executor command:my-agent-wrapper

The CLI checks the actual checkpoint diff, claimed changed paths, allowed paths, file/diff budgets, manifests/lockfiles, required commands, and final target state. It stops after one slice and never commits, pushes, publishes, deploys, or proceeds to another slice.

16. Process lifecycle and test topology

python .agentic/scripts/managed_command.py \
  --run-id ticket-031 --timeout 900 -- npm test

The wrapper records a durable lease and owns the process tree. POSIX uses a separate process group/session; Windows attempts a Job Object. Shutdown escalates from graceful termination to forced termination and checks for surviving owned descendants.

Test topology is a checked budget, not a vague request. Existing megafiles may be grandfathered but locked against growth. Split by stable behavior families and extract reusable fixture/drivers instead of creating ticket-number test files.

python .agentic/scripts/check_architecture_budgets.py .

17. Recovery and limitations

Stale plan

Generate a new plan. Do not edit fingerprints or integrity fields by hand.

Tooling failure

Read the tooling report and journal. Reviewed tracked/config paths are restored where promised. Caches, downloaded artifacts, node_modules, or external side effects may remain and are reported.

Skill conflict

Review the baseline/local/incoming conflict artifact, adjust selection or local content, and create a new plan. Do not overwrite the canonical project skill blindly.

Restructure blocker/failure

Resolve dynamic/generated/ambiguous references manually or reduce the move plan. Inspect the retained report/checkpoint and replan.

Alignment scope expansion

Stop. Return to Wayfinder or create a new alignment/nested plan. Do not broaden an executor task through prose.

Toolchain unavailable

The report must show unknown or the structural limitation. A scanner pass is not a compiler/analyzer/test pass.

No hidden remote authority: built-in commands do not commit, push, open a pull request, publish, deploy, or run a live paid model unless you explicitly configure and invoke an external command executor for one approved task.

18. Practical operating recipes

Current high-risk ticket

Wayfinder only if route decisions remain open
  → compile/freeze the current Lane-3 contract
  → one Codex implementer
  → spec/authority + code/test + ops review
  → targeted repair and invalidated-axis review
  → broad landing gate
  → serial commit/integration

Legacy repository with a long local ticket track

workspace-template adopt . --dry-run --plan-out ../adopt.json
workspace-template adopt . --apply-plan ../adopt.json
python .agentic/scripts/retrofit_docs.py docs --apply
python .agentic/scripts/retrofit_tickets.py docs/tickets/<track> --apply
python .agentic/scripts/validate_ticket_pack.py docs/tickets/<track>

Large test file that keeps growing

lock current size as the maximum
  → add no new behavior to the locked file
  → identify stable behavior families
  → extract fixture/driver support without production-logic duplication
  → move one family at a time under green verification
  → update the architecture baseline only after evidence passes

Agent workspace slowing down

stop new subagents
  → run Stop/SubagentStop lease guard
  → inspect only owned run leases
  → terminate owned process groups/job objects
  → verify zero owned descendants
  → reduce concurrency/MCP fan-out before continuing
