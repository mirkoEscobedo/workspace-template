# workspace-template 0.7.0

Version 0.7.0 is a methodology-rescue release. It starts from the clean 0.6.1
JavaScript baseline; the experimental native process owner, bootstrap
validators, native schemas, and generated evidence are intentionally excluded.
That work remains preserved as non-release forensic history.

## What changed

- Adaptive Delivery replaces Frontier/Wayfinder as the default methodology.
- Direct is the default mode. Ticketed and Governed require explicit admission
  signals.
- The execution state machine has numeric retry limits, hypothesis novelty,
  infrastructure-failure classification, and explicit replanning exits.
- Independent review uses a deterministic-to-inspection evidence ladder.
  Runtime debugging and interactive GUI inspection are conditional capabilities,
  not universal gates.
- Ordinary verification uses bounded foreground execution. Native whole-tree
  process ownership is optional and Governed rather than a universal gate.
- Configuration version 4 and profile version 3 record adaptive routing,
  repair/flaky limits, review policy, and durable-history policy.
- Existing v1-v3 configurations are migrated through the existing sealed
  inspect/plan/apply/verify transaction.
- Locally modified consumer skills are three-way merged. A retired managed file
  is deleted only when its installed content still matches its recorded
  baseline; otherwise the upgrade reports a conflict and preserves it.

## Compatibility window

The old `frontier-loop`, `execute-frontier`, `ticket-review`, and
`repair-ticket` names remain for this release as shims. They route to
`delivery-loop`, `execute-delivery`, `review-change`, and `repair-change` and
warn callers to update. Historical Frontier graphs are not revalidated or
resumed automatically.

## Release gate

Release candidates must pass source checks, the source suite, packed-artifact
checks, migration coverage, and disposable consumer canaries. Packaging is
allowed; publication, tagging, pushing, and merging require separate authority.

## Windows cleanup blocker carried into 0.8

The Windows SIGINT regression in `test/upgrade-cli.test.js` proves that bounded
foreground execution cannot guarantee cleanup for a package-manager command
that spawns an ordinary child and then a detached descendant. After native
whole-tree ownership became opt-in, interrupting the wrapper can orphan the
verification process tree. Two closure hypotheses did not produce a safe 0.7
repair without reinstating the excluded bootstrap process owner.

The test remains unchanged as the behavioral reproducer. Commit `6bf1a9f` is
the adaptive behavioral source baseline; 0.7 is not publishable while this gate
is unresolved. Native 0.8 must pass the reproducer through its own Windows
process containment and controlled cleanup before packaging can be accepted.
