# workspace-template 0.6.1

Candidate date: 2026-07-29

`0.6.1` is a reconciliation and safety release. It keeps the managed behavior
introduced in `0.6.0` while repairing Windows upgrade portability,
product-owned host-bundle boundaries, executable ticket validation, and
operational-receipt hygiene.

## Upgrade reconciliation

- Workspace-module verification commands survive Windows upgrade planning and
  apply.
- Generated workspace and verification hashes normalize CRLF/LF materialization
  so an equivalent checkout does not become a false conflict.
- Disposable verification copies retain the Git evidence needed by sealed
  checks while excluding only planned operational state.

## Host bundles and projections

- Adoption and upgrade preserve product-owned `.agents/`, `.codex/`,
  `.opencode/`, and `opencode.json` when `hostBundles` is `preserve`.
- Implicit direct sync and skill-update projection work is a successful
  `no-projection` operation when projections are disabled or host bundles are
  preserved.
- An explicit request for a protected projection target fails before any
  projection write.
- Managed projection mode remains compatible with the `0.6.0` behavior.

## Executable ticket contracts

- An executable ticket must include a `verification` object whose `commands`
  contains at least one nonblank exact command.
- Missing verification, missing or empty command lists, and blank-only commands
  are specification errors.
- Aggregate-only and historical records remain explicit non-executable
  exceptions.

## Process evidence

- Finalized lease receipts remain durable evidence but no longer make an
  otherwise clean workspace appear dirty during upgrade inspection.
- Active leases and surviving owned descendants remain completion blockers.
