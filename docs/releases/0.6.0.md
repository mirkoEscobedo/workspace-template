# Release 0.6.0 — Frontier Loop and safe retrofit

Version 0.6.0 consolidates the existing-repository retrofit program and the Frontier Loop research into one package that can either create a new agentic workspace or adopt an existing repository without treating it as a starter overlay.

## Seamless installed-workspace upgrades

Generated and adopted repositories use one command:

```bash
workspace-template upgrade .
workspace-template upgrade . --dry-run --json
workspace-template upgrade . --plan-out
workspace-template upgrade . --apply-plan <path>
```

Bare upgrade seals and atomically applies the package-current substrate.
Plan-out automatically creates a deterministic file under
`.agentic/plans/upgrades/` and prints the exact apply command. Apply preserves
product code, durable planning memory, repository-local presets, origin, and
adopted instruction ownership; it rejects drift and stale plans. Pre/staged/post
doctor and sealed verification checks surround a durable backup, with automatic
rollback and transaction evidence on failure.

- process leases and test-topology ratchets.

## Compatibility and migration

`create` remains the new-project command. Existing repositories should use `adopt` or its `retrofit` alias. Adoption never calls the create overlay and does not mutate source, tests, manifests, lockfiles, `README.md`, CI, or deployment files.

The package still recognizes and diagnoses version-1 generated profile/config state. New/adopted workspaces use the version-2 mode/current/preferred architecture model.

## Execution behavior

Frontier is local-file based. It does not require GitHub issues or event watchers. The earlier strict ticket-level sequence remains available inside one ticket: implement, independently review, repair failed findings, re-review, and land only after passing. Frontier adds parallel read-only preflight/review and dependency-aware readiness while retaining one writer by default.
